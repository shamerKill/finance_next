# AI Follow-up Paper Candidate Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 让历史 AI 运行的已完成强验证结果自动出现在 AI 跟进队列和今日任务中，提示用户进入 paper 候选证据复核，而不是继续停留在“查看验证进度”。

**Architecture:** 复用现有 `rankBacktestValidation()` 和历史运行 follow-up 管线。仅在 `aiRunFollowupItem()` 已识别某个历史运行启动过回测、且对应验证结果为 `优先 paper` 时新增一个高优先级 follow-up item；队列和今日任务继续使用 `open_link`，不自动采用 paper 候选或执行交易。

**Tech Stack:** Next.js client data helpers, Node.js `node:test`, TypeScript typecheck via `yarn typecheck`.

# Analysis (Populated by RESEARCH mode)
`client/data/ai-goal-preset.mjs` 中 `aiRunFollowupItem()` 已有 `startedBacktest` 分支。若 `bestStartedValidation.recommendation !== "优先 paper"`，它会生成 `redesign_validation`，让 AI 带失败证据重做蓝图。若 recommendation 是 `优先 paper`，当前逻辑会跳到默认 `validation_progress`，导致强验证结果没有被提升为 paper 候选。

`aiRunFollowupQueueFromRuns()` 会把 top item 转成 `primaryAction`，`aiDailyMissionFromState()` 在无 active analysis 时复用该动作，`aiNowActionFromState()` 又从今日任务生成首要动作。因此只要 follow-up item 和 primaryAction 映射正确，页面级“下一步”会自动变成 paper 候选证据复核链接。

# Proposed Solution (Populated by INNOVATE mode)
方案一是自动采用 paper 候选，但历史 run 缺少当前页面里的完整 `PaperCandidate` 对象，容易把用户推到不可执行或过度自动化的状态。

方案二是把历史强验证升级为 `paper_candidate_validation` follow-up，并提供 `/backtests/<runId>` 证据链接。它能让 AI 明确告诉用户该结果已经 paper-ready，同时保留人工复核市场风向、舆论、人性和执行摩擦的步骤。

方案三是从历史 run 重建完整 active analysis，再复用现有 `accept_paper_candidate` 流程。这个方案耦合更大，需要更多状态恢复规则，不适合作为当前最小增量。

采用方案二。
