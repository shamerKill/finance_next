**Goal:** 让 AI Money 顶部自主指令面板在没有 active analysis 时优先处理历史 AI run 的关键跟进，而不是总是提示启动新扫描。

**Tech Stack:** Next.js client data helpers, Node.js `node:test`, TypeScript typecheck via `yarn typecheck`.

# Task Description
优化 AI Money 使用路径，让用户不必在多个面板里判断下一步；如果历史 AI run 已经有强验证、弱验证重做或其它高优先级跟进，AI 自主指令面板应直接把这一步放到首位。

# Project Overview
`AIAutonomousCommandPanel` 是 AI Money 页面右侧最先出现的指令面板。当前 `aiAutonomousCommandFromState()` 在没有 active analysis 时优先使用 `aiCommandCenterFromState()` 的新扫描动作，即使 `aiNowActionFromState()` 已经从历史运行中推导出 `open_link`、`analyze_and_validate`、`validate_run` 等更具体的跟进动作。

# Analysis (Populated by RESEARCH mode)
`aiNowActionFromState()` 已经能在无 active analysis 时从 `aiDailyMissionFromState()` 和 `aiRunFollowupQueueFromRuns()` 读取历史跟进。例如历史强验证会生成 `open_link`，“查看 paper 候选证据”；历史弱验证会生成 `analyze_and_validate` 并携带 `proposedFormState`。

`aiAutonomousCommandFromState()` 当前无 active analysis 时使用 `commandCenter.primaryAction || nowAction.primaryAction || autopilot.primaryAction`。由于 command center 总会返回“启动 AI 扫描并验证”，历史跟进不会成为顶部自主指令。

# Proposed Solution (Populated by INNOVATE mode)
方案一是继续让用户在 Daily Mission / Now Action 里处理历史跟进，但这会让页面最突出的 AI 指令与真实下一步不一致。

方案二是在 `aiCommandCenterFromState()` 里直接改无分析状态的 primaryAction。这样会影响 command center 自身的空闲语义，容易把“全局命令中心”和“当前下一步”混在一起。

方案三是在 `aiAutonomousCommandFromState()` 中局部判断：如果无 active analysis 且 nowAction 不是普通扫描动作，就让 autonomous command 采用 nowAction；否则保留 command center 的启动扫描入口。采用方案三。
